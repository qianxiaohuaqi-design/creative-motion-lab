# 视觉与交互设计草案 v0.1

## 核心概念
从原作品“秩序 → 无序”的视觉叙事改编为“文字 → 云朵 → 风中消散”。

## 画面
- 画幅：先做适配电脑浏览器的全屏网页；后续可制作 9:16 竖屏版本。
- 背景：蓝天渐变；暂定上方 `#6CB9E8`、下方 `#B9E4F8`，可调整。
- 字体：先选轮廓清楚的粗体英文字；后续测试云朵材质。颜色以白色为主，带少量不规则边缘、半透明云絮和柔和阴影。
- 布局：文字仍有可读性，优先保持完整的句子构图。

## 运动系统
1. **初始排版**：单词整齐排列，维持短暂阅读时间。
2. **微风漂浮**：缓慢、方向相关的连续位移；不要每帧重抽随机目标，避免抖动。
3. **有序到松散**：缓慢增强偏移量、旋转幅度，必要时限制偏移防止过早无法辨认。
4. **点击消散**：首选以“整个单词”为交互单位；版本一使用模糊/透明度过渡；版本二升级为云絮粒子，向主风向飘走并渐隐。
5. **重新凝聚（已确定 A 方案）**：点击一个单词后，先淡化并分解成随风飘动的云絮；经过短暂停留（初步建议 2–3 秒，可调节），云絮重新聚合为相同的词。后续要防止重复点击打断未完成的重组。
6. **不点击时**：始终是轻缓的自动动画；后续再选择是否自动让文字逐渐散去。

## 技术与实现决策（暂定）
- DOM / CSS 对入门点击交互和整体文字布局更友好。
- Canvas 2D 对文字像素化、云雾粒子以及大量动态对象更自由。
- 噪声场（如 Perlin / Simplex noise）比完全独立的随机数适合柔和微风。
- 第一版不引入额外框架，第二版根据复杂度决定是否采用 p5.js。
- 仅凭截图不能认定原作者实际使用 HTML、p5.js 或任何指定工具。

## 开放问题
- 消散单位：第一版按**单词**点击；字母级交互可作为后续拓展。
- 云质感：柔软写实云层 / 诗意简约柔边 / 卡通泡泡云？
- 动画结尾：已确定 A —— 消散后自动重新凝聚。仍需通过实验确定消散/停顿/凝聚的时长。
- 文字内容：原创英文短句或中文诗句？（涉及中文粒子字形时需选择合适字体）
- 浏览器优先横屏还是先直接做抖音竖屏？

## 验收方向（非硬指标）
- 可以分辨文字，点击反馈明确但不突兀。
- 风场连续，邻近元素运动相似，节奏安静，不剧烈闪烁。
- 消散有颗粒层次而不只是突然消失。
- 用户自己能解释位置、时间、偏移、透明度、事件和粒子生命周期。

## v1.0 实际实现（2026-11-21）
- **已完成**：天空蓝背景、云质白字、单词及内部字母独立节点、温和微风、文字慢速失序、点击粒子消散与自动凝聚。
- 视觉策略：CSS 多层半透明字形、漫射光晕、蓝天空气层；不是未经声明的高精度物理体积云。
- 动画策略：正弦组合产生连续风场，单词间共享慢变化分量，字符内有小幅扰动；按时间推进并限制最大偏移，保留可读性。
- 粒子策略：在离屏 Canvas 采样原单词的像素位置，生成两层不同半径与透明度的云雾粒子；独立记录消散、停留、重组状态。浏览器缩放时考虑 DPR。
- 方案 A 已交付：单词散开后自动回到同一个词；用户无需手动刷新。
- 原有设计稿中的“未实现”描述是历史阶段记录，以 TASKS.md、TESTING.md 为当前完成依据。
